1. 结论先行

不建议第一步替换 AVDN 的 BERT/ET/ViT 主干。当前最有希望、成本最低的改进点在现有 Qwen3‑VL + SAM3 工具循环外围：先把自然语言事件形式化为可验证几何约束，再增加低置信度时的主动补看与工具式批判，最后利用既有 JSON 轨迹建立跨样本经验/技能记忆。

首选组合GCA‑Lite + CRITIC约束计划、验证后执行
最直接补洞ProFocus‑Lite失败前主动裁剪 / 第二视图
跨样本学习XSkill‑Lite不更新参数的经验 + 技能库
不优先大模型重训AstraNav / OctoNav / 3D‑VLM
建议最小论文主张：提出一个面向航拍对话导航的“约束—验证—恢复—记忆”代理层，在冻结导航与视觉基础模型的前提下，提高 test‑unseen 的 SR/SPL/GP，并同步降低单次成功所需的无效视觉调用。

推荐实施顺序

  1. P0 / 1–3 天：GCA‑Lite 事件约束对象 + CRITIC‑Lite 几何/候选验证器；只改 Agent orchestration，不训练。
  2. P0 / 再 2–4 天：ProFocus‑Lite：仅在证据不足时触发目标 crop、相邻尺度或航向偏转视图，失败不立即终止。
  3. P1 / 3–7 天：XSkill‑Lite 或 AWM：从成功/失败 `search_steps` 提取经验与工作流，top‑k 检索到后续路线上下文。
  4. P1 / 2–3 天：HiAgent 式事件分块与摘要，控制长对话、多个事件和候选证据的上下文膨胀。
  5. 有稳定提升后：再考虑 TrajRAG‑Lite 的几何‑语义轨迹库或 AFlow 的离线工作流搜索。

2. 当前工程诊断：为什么适合做 Agent 层改进

原始学习基线

  • BERT 文本表示；Darknet/ViT 视觉特征。
  • LSTM 与 Embodied Transformer 两套导航器。
  • 连续 4 维输出：平面位移、视野尺度/高度、进度。
  • 默认最多 10 步，训练 200k iterations；Python 3.9 / Torch 1.11 旧栈。

  • 视觉失败立即终止后续事件；默认只看 scale‑5 主视图。

4. 六个重点方法：如何映射到当前数据集与代码

4.1 GCA‑Lite：把“语言理解”与“几何执行”真正解耦

首选Training‑freeCVPR 2026
9.2 / 10

GCA 的关键不是完整 3D 工具栈，而是先生成形式化任务约束，再让后续工具调用只能在该约束内计算。当前工程已经有 heading、GPS、candidate mask、forward sector 和 relation，缺的正是一个不可变的约束对象。

建议新增最小结构

{
  "reference_frame": "heading_up",
  "origin": "current_agent_position",
  "target_event": "e3",
  "relation": "pass_left_of",
  "allowed_sector_deg": [-15, 15],
  "objective": "select target then compute legal waypoint",
  "hard_checks": ["registered_candidate", "target_role",
                  "forward_intersection", "non_duplicate"]
}

落点位置

  • 在 `run_sequential_plan()` 每个 `REACH/AVOID` 前构造 constraint。
  • 候选搜索提示词只读语义部分；几何模块只读 constraint + candidate。
  • 将所有 hard check 结果写入 `search_steps[].verification`。
  • 不引入 Ray/Open3D；只参考官方 repo 的 analyst → planner → executor 分层。

可验证消融：无约束 / 仅输出校验 / 完整 constraint。重点看 relation 错误率、非法落点率、SR/SPL。

4.2 CRITIC‑Lite：只在工具证据冲突时自我修正

首选Training‑freeICLR 2024
9.0 / 10

CRITIC 强调“不能只让模型反思，必须让外部工具提供可核验反馈”。这与已有的 deterministic geometry 极其契合。建议避免无条件增加一次模型调用，而使用证据门控。

触发条件工具反馈允许的修正
候选不与前向扇区相交，或距离显著异常方向差、最小像素距离、mask/sector 交点换同次注册候选，或请求一次补看
relation‑aware point 不在允许区域point-in-mask / side-of-object / clearance 结果只重算 point，不得更换目标
多目标计数或重复实例candidate_id、地理距离、IoU/重复判定选择未使用实例
证据充分且所有硬约束通过PASS不调用 critic，直接执行

成本控制：最多一次 critique→revise；将“修正后仍失败”作为可分析错误，不开启无限循环。

4.3 ProFocus‑Lite：从“单图失败”改为“按需补证据”

首选概念暂无公开代码CVPR 2026
8.8 / 10

论文使用主动感知与 BD‑MCTS。对本工程无需先实现完整树搜索，最小版本只增加一个“缺什么证据”的结构化判断和三种受限视觉动作：

  • 目标过小：以候选/语义区域为中心裁剪放大，再送 Qwen 或 SAM3。
  • 前向不可见但锚点可见：生成 ±15°/±30° 航向偏移视图，最多二选一。
  • SAM 无候选：使用一次上位类别/外观短语重写；仍失败才终止。
与当前代码的直接关系：现有 README 明确只提交 scale‑5 主视图，失败不做第二尺度且整条路线停止；因此该消融的因果链最清晰，预期首先提升目标召回与 oracle SR。

4.4 XSkill‑Lite：把日志变成可复用的视觉经验与技能

强推荐完整官方代码ICML 2026
8.7 / 10

XSkill 将知识拆成两类：action‑level experience（局部战术）与 task‑level skill（结构化流程），且提取与检索都能参考图像。官方仓库已有 trajectory summary、cross‑rollout critique、skill builder、experience merge、embedding cache 和 top‑k retrieval；是本次源码核查中最接近当前工具代理形态的实现。

AVDN Experience 示例

{
  "trigger": "small target + no SAM candidate",
  "evidence": "scale5; target=parking booth",
  "action": "crop anchor region; query superclass",
  "outcome": "candidate found on retry",
  "scope": "overhead urban maps",
  "confidence": 0.82
}

AVDN Skill 示例

SKILL: pass-left-of landmark
1. Lock heading-up reference frame.
2. Select complete target instance.
3. Verify forward-sector intersection.
4. Compute waypoint on target's left side.
5. Preserve clearance; execute once.
  • 只从官方指标成功或人工确认的轨迹提炼正经验；失败轨迹先做错误归因再写入“avoid rule”。
  • 按 `target category + relation + scene type + failure signature` 检索 top‑3，避免把整条相似路线塞进上下文。
  • 官方实现要求 Python 3.11 / Torch 2.8；建议抽取纯 JSON/embedding 模块到 sidecar，不污染 Python 3.9/Torch 1.11 导航环境。

4.5 HiAgent：event 即 subgoal，完成后压缩历史

低风险完整官方代码ACL 2025
8.2 / 10

HiAgent 在生成动作前显式提出 subgoal，完成后把该段 action‑observation 历史替换为摘要，只保留与当前 subgoal 相关的工作记忆。论文报告跨五个长程任务获得约 2× 成功率并减少 3.8 个平均步骤；这些数字来自原论文任务，不能直接外推到 AVDN。

  • 将每个解析事件作为一个 subgoal，不另做复杂分解。
  • 事件完成后保留：目标类别、candidate_id、最终 GPS、heading、relation、验证结果、失败原因。
  • 原始图像和候选 sheet 留在磁盘，以 artifact path 引用，不重复送入后续事件。
  • 官方核心实现很轻：agent 约 299 行，trajectory summarizer 独立；可直接参考逻辑重写。

4.6 TrajRAG‑Lite：中期形成更“导航专属”的方法贡献

中期方法点暂无公开代码CVPR 2026
8.0 / 10

TrajRAG 将过往导航压缩为 topo‑polar 几何‑语义经验，并进行分层检索。AVDN 天然拥有 GPS、航向、视野角和事件语义，比室内 RGB‑D 更容易构造 2D 版本：

route memory = [
  (event_type, target_semantics, relation,
   distance_bin, bearing_bin, scale_bin,
   detector_outcome, verifier_outcome)
]

建议先用离散 polar bins + BM25/embedding 做轻量实现，不必复现论文 3D frontier。与 XSkill 的区别是：XSkill 存“怎么做”，TrajRAG 存“在什么几何‑语义局面下什么做法成功”。两者可形成互补消融。

建议的最终 Agent 控制流

for event in plan.events:
    constraint = formalize(event, heading, current_position)
    memory = retrieve_experience(event, constraint, top_k=3)
    observation = render_primary_view(scale=5)
    proposal = qwen_sam_select(observation, constraint.semantic, memory)

    verdict = deterministic_verify(proposal, constraint)
    if verdict.is_uncertain and recovery_budget > 0:
        observation += active_perception(verdict.missing_evidence)
        proposal = revise_with_tool_feedback(proposal, verdict, observation)
        verdict = deterministic_verify(proposal, constraint)

    if not verdict.pass:
        record_failure_and_stop(event, verdict)
    execute(proposal.waypoint)
    summarize_subgoal(event, proposal, verdict)
record_experience_if_evidence_is_reliable()

OctoNav‑R1 · CVPR 2026Think‑Before‑Action、SFT + GRPO + online RL以项目后续发布为准数据构建与三阶段训练成本高
SAGE · ACL 2026用 GRPO 学习如何验证和应用 skill library论文页未给可快速复用入口应在 XSkill‑Lite 证明技能库有效后再考虑 RL
Memory‑R1 · ACL 2026Memory Manager + Answer Agent 主动 ADD/UPDATE/DELETE/NOOP需再核对代码发布面向对话记忆且需 PPO/GRPO；可借鉴操作 schema
作为基础对照而非“最新主方法”
  • LATS（ICML 2024）：MCTS + value + reflection，源码完整；但当前环境不可廉价回滚，直接移植会增加大量调用。
  • ExpeL（AAAI 2024 Oral）：跨 trial 经验学习，源码完整；适合作为 XSkill/AWM 的经典 baseline。
  • Agent‑Pro（ACL 2024）：policy-level reflection，官方代码主要耦合棋牌游戏环境；概念可用，代码迁移价值有限。

源码快照证据

  • GCA：102 个文件 / 74 Python；LangGraph + Ray + Open3D 等完整工具工作流，适合“读结构、轻移植”，不适合塞进旧环境。

  • AWM：55 个文件 / 29 Python；工作流文本、FAISS 检索和两个 web benchmark 实现齐全。
  • HiAgent：仓库很大但核心逻辑简单；`ours_agent.py` 约 299 行，另有独立 trajectory summarizer。
  • EfficientNav：7 个文件 / 3 Python；主脚本约 1,032 行并直接加载大模型，复现完整论文系统的可维护性一般。
  • EvoNav：5 个静态文件 / 0 Python；不能将“仓库存在”误写为“代码已发布”。
