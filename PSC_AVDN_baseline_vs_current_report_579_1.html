1. 结论先行

当前项目并不是在官方 PSC-AVDN 上做“小幅增强”，而是重写了核心协议：从“每个 INS 解析成方向 + 目的地、MLLM 多步搜索并确认”改为“完整对话解析成事件图、逐事件执行、Qwen 调用 SAM3 候选工具”。这修复了方向与中间地标的表达能力，但同时移除了官方方法最关键的多尺度观测、跨步视觉/网格记忆和向前探索。

579__1 首段航向111° → 90°当前修复绝对/相对方向混用
终点中心距离149.8 → 94.9 m更接近，但仍未到达
最终 IoU0 → 0没有指标改进
最终状态false → false当前在 e4 找不到 house 后停止
最关键的失败链：当前解析已把 “road → 8 点钟 → house” 拆对；但 `house` 被发送给 SAM3 后得到 0 个候选，Qwen 被禁止在候选集合之外选择图中建筑，于是目标事件立即失败。当前又只有单尺度、单位置、一次搜索，没有基线的 3 次 × 120 m 前向探索或网格记忆来恢复。
指标不可直接宣称整体优劣：当前默认 `sample3` 只有 2 条轨迹，官方完整 test-unseen-full 有 432 条。本报告只对完全相同的 `579__1` 原始对象做单例对照；不能把 2 条样本的汇总指标与论文/全量基线并列。

4. 输入的具体不同

4.1 数据集层：原始 observation 基本相同

输入层官方基线当前代码
原始字段instructions、map_name、route_index、初始 angle、gt_path_corners、destination、地图 GPS 边界/比例、TIF 地图。
默认集合Parse 默认 datasets/FULL + datasets/AVDN / test_unseen_full；Search 文件头却默认 val_seen_full，需人工改顶部常量。Parse 与执行器都固定到 datasets/sample3 / test_unseen_full；只有 2 条诊断轨迹。
运行时环境依赖项目根目录 AVDN src/env.py。同样依赖根目录 src/env.py；该文件算法与 AVDN 官方一致。

4.2 解析模型实际看到的文字完全不同

维度官方基线当前代码
切分正则只抽取每个 [INS]；忽略 [QUE]，每条 INS 单独调用一次。保留所有 [INS]/[QUE]，按 1、2、3…统一编号，一次提交完整对话。
元数据模型用户消息只有单条 instruction；系统提示还写着“初始朝向假定为 12:00”。用户消息显式包含 trajectory_id、真实 starting_heading 和完整编号对话。
任务只产出一行：Next movement direction + Destination description。产出一个完整 JSON：轨迹 ID、初始航向、实体、按时间排序的 TURN/MOVE/REACH/AVOID 事件。
上下文提示声称可结合对话上下文，但模型调用中没有 QUE，也没有其他 INS。后续 QUE/INS 可否定早期判断、把局部“destination”改成中间点、补充视觉描述。
结构保障正则解析失败时把整段输出塞进 dest，缺少模式验证。结构归一化 + 约束验证；失败后最多一次修复调用；仍失败写 failures 并中断整体编译。

4.3 视觉模型实际看到的图像与结构不同

维度官方基线当前代码
第一阶段视觉输入同位置同航向的 scale 5 主图、scale 3 窄图、scale 7 宽图、北向 minimap（含轨迹）。主动配置只有一张 768×768、scale 5、heading-up 主图。
目标候选Qwen 原生视觉直接输出主图 bbox；无外部分割模型。Qwen 调 find_visual_candidates，用 1–4 个短概念请求 SAM3；只允许从已注册 target 候选选一个。
发给 Qwen 的候选元数据不适用。精简到 candidate ID、概念与 ±15° 前向扇区相交/最短像素距离；候选分数不用于 Qwen 破平局。
导航点使用 bbox 中心，或根据上下半区执行接近/确认。选定候选后开全新上下文，给原图 + 固定 mask/bbox 图，由 Qwen 返回关系感知像素点。
最终框搜索 bbox 后，再在候选附近多尺度确认，确认框决定 zoom crop。只有最终 goal 另开干净上下文返回 tight bbox；非 goal 只保留 SAM bbox 证据。
本次实际后端仅 MLLM。qwen3-vl-plus + sam3；579 运行 health 中 DINOv3 loaded=false。
论文将 PSC-AVDN 的 SSM 定义为多尺度视觉、历史视觉记忆、更新的语义网格三部分，并强调原生 MLLM、无外部依赖。当前代码引入 SAM3，同时把主动输入缩减成单尺度单帧，因此属于方法重构，而非严格保持 SSM 的模块替换。

5. 输出的具体不同

5.1 解析输出

项目官方基线当前代码
主格式CSV，一条 INS 一行。instruction_plans.jsonl，一条完整轨迹一行；另写 CSV 事件摘要。
字段instr_id, step_idx, instruction, move_dir, dest, via, angle_before, angle_after, raw_output。format_version, plan_id, turns, parser_model, repaired, plan.entities, plan.events；事件带 frame/angle/relation/constraints/count/side。
方向语义绝对角会在后处理转成相对 clock 字符串，语义由列名/阶段隐含。方向对象显式区分 frame=absolute|relative，执行器按 frame 求解。
失败API/解析失败通常产生空输出并继续。记录模型调试与 failure JSONL；任一计划失败最终抛错，偏向 fail-fast。

5.2 导航输出

项目官方基线当前代码
兼容字段instr_id, trajectory, path_corners, progress, gt_path_corners, final_iou, path_length, success。
当前新增—physical_trajectory、每事件 search_steps、event_progress、completed_event_ids、terminated、原因、工具 trace、服务 health、最终目标 bbox/mask。
轨迹点含义把起始/转向视野、每个搜索视野、回退视野、zoom crop 都追加到 predicted_boxes；因此 path length 混合“物理移动”和“观察框”。只在事件完成后记录物理 pose；失败事件不追加 pose。路径更干净，但不能与基线路径长度直接比较。
path heading每个 path corner 都写初始航向，而不是当时航向。每个 pose 写实际事件后航向。
内部成功final_iou > 0.3；两边随后也调用 AVDN env.eval_metrics。
官方环境成功项目现有诊断显示要求 final IoU ≥ 0.4，并要求预测/GT 多边形分别严格包含对方中心。不要把内部 success 与官方 SR 混为一谈。
当前评测接口的潜在脱节：最终 goal 成功时，工具链会生成 final_target_grounding.bbox_latlng，但 final_iou 仍对“平移后的起始视野 footprint”计算；搜索返回的 zoom corners 和最终 bbox 没有进入 physical_boxes。因此更准的最终框不一定反映在当前内部 IoU 上。

6.1 状态和记忆

  • 基线：last_grid_5x5 跨搜索步传递；minimap 融合此前 crop、位置、航向和轨迹；这与论文 SSM 的三类记忆对应。
  • 当前：事件完成 ID 会进入 active-event JSON，原始对话、历史航向和经纬度被明确省略；RouteViewHistory 会收集主图，但之后没有传给 search_engine 或 grounding_agent，属于当前主动路径中的未消费状态。
  • 当前目录中的窄图/宽图/minimap：部分是 8 月 20 日旧运行残留；8 月 22 日最新 prediction.json 的 view_scales 只有 {main: 5.0}，不可据目录文件名误判当前仍在多尺度运行。

6.2 几何

  • 基线直接在经纬度 degree delta 上旋转视野矩形，并在透视变换前裁切越界源角点，纬度变化时物理形状会失真。
  • 当前先在局部 north/east 米制坐标旋转，再换回经纬度；越界部分由 OpenCV border 采样，不扭曲地理映射。这是明确的确定性修复。
  • 当前用 ViewGeoTransform 做像素↔经纬度映射，并对 PASS/CROSS 等关系在目标点后固定越过 30 m。

8. 为什么修改很多却没有指标改进

优先级证据链对结果的影响
P0类别词与航拍语义不匹配：目标文字是 house，图中更像工业建筑/仓库；SAM3 返回 0 候选。Qwen 无权越过候选集合；无候选即必失败。这正是 579 当前直接原因。
P0搜索从多步退化为单步：当前 step_n=1，没有失败后前移、重拍、改写概念继续搜索。一次视觉漏检立刻终止整个路线；基线至少有 3 个位姿。
P0SSM 主动路径被移除：只用 scale 5；没有当前运行的窄/宽图、minimap、5×5 更新网格；RouteViewHistory 未消费。缺少小目标细节、全局位置和跨步一致性，而这些正是论文报告增益来源。
P1评测输出未接上最终 bbox：生成的 final bbox 与 zoom corners 不进入 final IoU 的 physical_boxes。即使视觉定位变准，内部 IoU 也可能看不到增益。
P1解析协议与执行协议虽更强，但新增更多硬失败点：计划必须完全合法、服务必须预检通过、候选必须合法、point 必须合法、任一事件失败即停。可解释性提高，episode 完成率却可能因级联门控下降。
P1验证集太小：当前默认只有 2 条诊断轨迹。不能判断总体提升；也容易针对样例反复修改而无稳定回归信号。
P2遗留代码与产物混杂：search_engine.py 仍保留旧 runner；目录有旧 multi-scale/e5 产物。容易把非主动代码/旧图片当成当前流程，导致调试结论错误。
并非所有修改都无效：完整对话事件计划、方向 frame、米制几何、逐事件日志、SAM mask 证据和服务预检都提升了正确性或可诊断性。问题是这些收益被最终目标漏检、搜索恢复能力下降和评测接口脱节抵消，因此 `579__1` 的最终成功指标仍未改善。

9. 建议的修复/实验优先级

  1. 先做可比评测：固定同一 40–100 条 test-unseen-full 子集、同一模型版本/温度/后端，保存基线与当前两套原始输出；同时报告官方 env.eval_metrics 的 SPL/SR/GP，而不是只看内部 IoU>0.3。
  2. 恢复 bounded multi-step search：目标无候选时允许 2–3 个位姿，每次前移前保持事件/关系约束；失败时最多一次同义上位词改写（例如 house → building/structure），仍需留审计记录。
  3. 恢复 SSM 的有效部分：至少把 scale 3/5/7 和 north-up 轨迹 minimap 送入候选选择；或者把已收集的 RouteViewHistory 真正拼成 memory canvas，再做受控消融。
  4. 软化 SAM 硬门控：SAM 无候选时允许 Qwen 在原图提出一个待验证区域，再用 bbox/point prompt 或备用 Grounded-SAM2 验证；不要让“文本类别词不匹配”直接等价于“目标不存在”。
  5. 统一评测几何：明确 AVDN 的 path_corners 应表示无人机视野还是目标框；若以最终目标定位为任务输出，应让 final_target_grounding.bbox_latlng 参与相应定位 IoU，同时保持导航视野轨迹用于 SPL/GP。
  6. 做最小消融矩阵：事件解析 only、+ 单步 SAM、+ 多步、+ 多尺度、+ memory、+ final-bbox metric。每次只增加一个变量，才能知道“修改很多”为何没有提升。
建议首先验证的 579__1 恢复策略：
1) 保留当前 e1/e2/e3（方向与过路已经正确）；
2) e4 第一次 query="house" 为 0 后，第二次 query="building"；
3) 同时提供 scale 3/5/7 与 north-up minimap；
4) 若仍为 0，沿 330° 前移一个小步再观测，而不是终止；
5) 记录每次候选集合，并用同一官方 env 指标复核。
